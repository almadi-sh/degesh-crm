# Дорожная карта CRM/ERP + AI (единый план)

## Цель
Построить production-ready процесс, где заявки, закупка, растаможка, бронирование, отгрузка и оплаты ведутся через backend workflow, а AI даёт рекомендации и не выполняет критичные записи напрямую.

## Фаза 1 — Основа процессной модели
1. Разделить сущности:
   - `requests` — входящие бизнес-заявки;
   - `process_instances` — экземпляры workflow;
   - `process_transitions` — история переходов состояний.
2. Реализовать серверные переходы state machine с валидацией правил.
3. Добавить `domain_events` (audit trail) для каждого перехода и ключевого действия.

## Фаза 2 — Ядро остатков и броней
1. Ввести лотный/партионный учёт (`procurement_lots` / `stock_batches`).
2. Сохранять брони отдельными записями с привязкой к `lot_id`.
3. Обеспечить атомарность бронирования:
   - row lock по лоту;
   - CHECK constraints на неотрицательные остатки;
   - идемпотентность команды бронирования.

## Фаза 3 — Доступы, задачи и уведомления
1. Внедрить RBAC + row-level visibility:
   - sales видит свои брони + агрегированный доступный остаток;
   - manager видит полную картину.
2. Разделить сущности:
   - `notifications` — информационные события;
   - `tasks` — действия с ответственным и сроком.
3. Создавать задачи из переходов workflow, а не из UI-обходов.

## Фаза 4 — Документы и комплаенс
1. Ввести реестр `documents` с жизненным циклом:
   - uploaded, pending_review, accepted, rejected, expired.
2. Добавить правила переходов (`required_documents_rules`) для статусных gate-ов.
3. Разрешать переходы по растаможке/отгрузке только при полном и верифицированном комплекте документов.

## Фаза 5 — Аналитика SLA и AI-слой
1. Считать SLA-метрики из событий:
   - time-to-contract;
   - time-to-customs;
   - time-to-shipment;
   - payment delay.
2. Ввести журнал `ai_decisions`:
   - модель, версия промпта, input_snapshot, output, latency, approval.
3. Ограничить AI-операции:
   - предлагать следующий шаг;
   - объяснять риски;
   - формировать черновики действий;
   - не писать напрямую в критичные ERP-сущности.
